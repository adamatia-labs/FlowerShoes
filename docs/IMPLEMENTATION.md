# 꽃신 구현 노트

설계안 v6(+ 아래 v7 수정)을 코드로 옮기면서 정한 것과 진행 상황을 적는다.
설계 원문은 별도로 관리하고, 이 문서는 **설계와 코드가 어디서 만나는지**만 다룬다.

## v7 수정 (v6 리뷰 반영, 7-3-A 백업 복원)

1. **새 폰 토큰 전달**
   - 승인 문서가 생기면 트리거 `onRotationApproved`가 기기 상태만 바꾼다. 새 기기는 active, 옛 기기는 active=false.
   - 새 폰은 callable `finalizeDevice`를 직접 부른다. 이 함수는 **새 기기 키로 서명한 챌린지**를 확인하고 커스텀 토큰을 발급한 뒤 `revokeRefreshTokens`를 호출한다.
   - 서명을 확인하는 이유: 같은 uid의 옛 폰이 이 함수를 먼저 불러 새 세션을 가져가지 못하게 하기 위해서다.
2. **백업 이후 빠진 부분 메우기**
   - 지수 폰은 받은 Op을 보관하지 않으므로 "옛 스트림 seq 이후"를 따로 걸러 낼 수 없다.
   - 그래서 **민준이 쓴 행 전체와, 민준 옛 기기가 마지막으로 수정한 Event 전체**를 스냅샷으로 보낸다. 받는 쪽은 lamport로 병합한다.
   - "옛 스트림 seq" 개념은 쓰지 않는다.
3. **오래된 백업 키**
   - 백업 속 epoch 키로 만든 MAC을 지수 폰이 검증할 수 없으면 자동 승인하지 않는다. 이런 경우는 옛 epoch가 31일 보관 기간을 넘겨 지워졌을 때 생긴다.
   - 대신 **7-3-B(상대 넘겨주기)로 안내**한다.
4. **연달아 오는 교체**
   - 24시간 안에 두 번째 교체 요청이 오면 자동 승인하지 않고 SAS로 확인한다. 도난 폰과 진짜 주인이 번갈아 교체를 시도하는 경우를 막기 위해서다.
5. **탈퇴**
   - 커스텀 토큰으로 다시 로그인한 기기는 재인증을 할 수 없다. 그래서 callable 함수가 Admin SDK로 탈퇴를 처리한다.

## 구현하면서 정한 것

| 항목 | 설계 | 구현 | 이유 |
|---|---|---|---|
| 백업 키 파생 | HKDF | BLAKE2b 키 해시(용도 문자열) | libsodium에 HKDF가 없다. 같은 성질(용도별 독립 키)을 BLAKE2b로 얻는다 |
| 폐기 기기 Op 거부 | seq 주, createdAt 보조 | **seq로만** 판정 | createdAt은 시계가 어긋나면 정상 Op을 버린다. 로그용으로만 남긴다 |
| 리플레이 길이 | 3~8초, 마지막 150ms 크로스페이드 | 그리기는 최대 7,850ms, 그 뒤 150ms 크로스페이드(합계 ≤ 8초) | 마지막 획이 그려지는 도중에 덮이지 않게 |
| 그림 문서 압축 | TLV + zstd | 엔진은 TLV까지, zstd는 플랫폼 쪽(`:core:media`) | zstd는 순수 Kotlin 구현이 없다 |
| 전역일 계산 | — | 민법 기간 계산(같은 날의 전날, 없으면 그 달 말일) | 8월 31일 입대 같은 경우를 맞추기 위해 |
| 복무 규칙 기본값 | 시행일별 표 | 육군·해병 18, 해군 20, 공군 22, 사회복무 21개월, 진급 2/6/6 | **출시 전 병무청 공지와 대조 필요** |
