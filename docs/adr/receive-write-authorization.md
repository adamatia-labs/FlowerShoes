# 수신의 실제 쓰기 시점에 관계와 기기 재확인

이슈 #131의 수신 경합을 다룬다. `relationshipMutex`는 같은 `AppDatabase` 인스턴스만 보호한다. 다운로드를 기다리는 동안 다른 인스턴스/프로세스가 연결을 해제하거나 송신 기기를 교체할 수 있으므로 처음 읽은 행과 서명 검증만으로 쓰기를 허용하지 않는다.

## 결정

- 서명 확인에 사용한 관계 행과 송신 기기 행, 스트림/번호를 수신 작업에 묶는다.
- 네트워크 다운로드와 복호화는 DB 트랜잭션 밖에서 수행한다.
- 첨부 파일 설치와 행/연결 표식 저장, 충돌 표식 저장, 마지막 본문/수신 커서 반영은 각각 SQLite immediate 쓰기 트랜잭션에서 현재 관계와 기기를 다시 확인한 뒤 수행한다. 파일 설치 자체도 이 경계 안에 있다.
- 관계 행(키 epoch/봉투 포함), 기기 소유자/공개키/등록·폐기 상태가 달라지면 수신을 거부한다. 폐기 cutoff는 본문 처리와 같은 판정 함수를 파일 쓰기 전에도 적용한다.
- 취소는 호출자에게 전파한다. 이미 정상 저장한 첨부의 연결 표식은 유지하여 재시작·재전송으로 이어받는다. 관계 변경 이전에 저장된 파일의 보관/삭제는 연결 해제 정책이 담당한다.

## 검증과 남은 범위

JVM 테스트는 같은 실제 SQLite 파일을 여는 별도 Room 인스턴스로 다운로드 중 연결 해제·새 관계 연결·동일 관계의 키 교체·송신 키/소유자/폐기 상태/cutoff 변경을 재현한다. 첨부 저장 후 본문 직전의 변경과 첨부 없는 편지도 확인한다. 기존 첨부 충돌·취소·재전송 테스트를 유지한다.

이 변경만으로 #131을 닫지 않는다. 서버 연결 해제부터 파일/설정 정리 완료까지의 영구 작업 기록, KEEP/WIPE 선택 복구, 계정 탈퇴 복구, 이전 화면의 쓰기와 새 연결 수락 순서 제어는 별도 작업으로 남는다. 같은 식별자의 관계를 해제 후 완전히 같은 행으로 복원하는 ABA까지 판별할 영구 세대 식별자도 그 수명주기 작업에서 다룬다.
