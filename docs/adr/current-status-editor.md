# 내 상태 입력과 상대 상태 위젯

이슈 #158에서 상태 위젯의 데이터 저장 API는 있었지만 앱에서 입력하는 경로가 없었다. 연결된 홈의 `내 상태`에서 상태명과 표시 기간을 설정하고, 같은 시트에서 기존 상태를 지운다. 1시간, 오늘 자정, 내일 오전 8시, 직접 지울 때까지를 제공하며 기존 상태를 열면 원래 만료 시각을 유지한다. 날짜 경계는 앱의 서울 시간대를 따른다.

Figma 위젯 `383:5321` / 상태 카드 `384:5340`과 v2 컴포넌트 `340:89`를 확인했다. 별도의 상태 입력 화면은 없어 기존 입력·하단 시트·선택 행·버튼을 조합했다. 곰신/군인과 밝음/어두움 네 테마를 따른다. 상태 본문은 분석 이벤트에 기록하지 않는다.

편집 시작 시 계정/기기/로그인 세대와 관계 행을 보관한다. 저장·삭제는 DataStore → Room 순서로 잠그고 원래 계정, 관계, 키 세대와 정리 작업 부재를 재확인한다. 계정 전환이나 재연결 후 오래된 화면의 입력을 새 상대에게 보내지 않는다. 저장 실패는 시트에 표시하며 중복 제출과 저장 중 입력을 막는다.

상태 삭제는 즉시 만료된 빈 상태를 기존 StatusPut 연산으로 기록한다. 최신 상태가 만료되면 이전 무기한 상태를 되살리지 않는다. 구독 중인 상태는 DB 변경이 없어도 30초 주기로 만료를 반영한다. 스키마나 암호화 프로토콜은 변경하지 않는다.

JVM 테스트는 만료, 삭제, 계정 전환/ABA, 별도 DB 연결의 재연결, 서울 날짜 경계와 UI 비활성화를 검증한다. Android 에뮬레이터 테스트는 실제 Room/DataStore와 화면 조작으로 저장·삭제 → outbox → 수신 적용 → 상대 위젯 스냅샷을 확인한다. 이 테스트의 전달 구간은 서명 검증·복호화 이후부터이며 실제 Firebase 전송 검증으로 간주하지 않는다.

이 변경만으로 #158을 닫지 않는다. 그림 프레임 정책과 iOS 위젯 관찰 항목은 별도 확인 대상이다.
