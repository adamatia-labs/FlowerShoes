# Apple 토큰 등록 실패 안내와 재확인

이슈 #106의 `appleStoreToken` 실패 무시와 Apple 로그인 방법 연결 시 코드 누락을 수정한다. 인증 자체가 성공한 뒤 토큰 등록/준비 확인이 실패하면 로그인을 실패로 가장하지 않고 안내를 보여 준다. 사용자는 다시 확인하거나 수동 연결 해제 가능성을 알고 계속할 수 있다. 계정 설정 저장과 기기 변경 화면 이동은 이 안내 뒤에 수행한다.

로그인 방법 화면은 Apple의 준비 여부를 서버에서 다시 읽는다. 등록 정보가 없거나 신원이 다르거나 불확정 코드 교환이 남으면 `연결됨 · 확인 필요`로 표시한다. iOS 재확인은 현재 Firebase 사용자를 재인증해 새 일회용 코드를 얻는다. 이미 소비됐을 수 있는 코드를 저장하거나 반복 전송하지 않는다. Android의 Firebase OAuth 웹 흐름은 앱에 authorization code를 반환하지 않으므로 서버 상태를 다시 확인하고 준비되지 않았으면 Apple 계정의 수동 해제 방법을 안내한다.

Apple을 Google 등 다른 로그인 방법의 계정에 연결한 뒤에도 갱신된 Firebase ID 토큰의 `identities.apple.com`으로 등록을 허용한다. Apple HTTPS 토큰 교환 응답의 id_token에서 issuer, audience, 만료와 subject를 확인하고 로그인된 Apple 신원과 일치할 때만 refresh token을 저장한다. 이 응답 파서는 임의의 외부 JWT 서명 검증기가 아니다. 잘못된 신원으로 발급된 토큰은 저장하지 않고 폐기를 시도한다.

클라이언트는 기대 Firebase UID를 함께 보내고 서버는 인증된 UID와 비교한다. 안내 도중이나 DataStore 쓰기 차례를 기다리는 동안 SDK 계정이 바뀌었으면 원래 계정을 로컬 설정에 적용하지 않는다. 실제 설정 transform 안에서 UID를 재확인한다. 취소를 저장 실패로 삼키지 않으며 확인 중 중복 제출을 막는다. 이 검사만으로 #131의 모든 화면 세대/로그아웃 경합을 해결했다고 보지 않는다.

토큰이나 Apple 식별자는 준비 상태 조회 응답에 포함하지 않는다. 오래된 등록에서 신원 확인 정보가 없으면 준비 완료를 추측하지 않는다. 탈퇴 시에도 현재 Apple 신원과 일치하는 토큰의 폐기가 확인된 경우에만 자동 해제 완료를 알린다. 저장 또는 발급 토큰 폐기를 확정한 교환만 pending 카운터에서 뺀다. 응답을 잃어 발급 여부가 불확실하면 표시를 남기고 수동 안내를 유지한다. 앱 분석 이벤트에 사용자·토큰 정보를 추가하지 않는다.

검증은 Node 단위 테스트와 로컬 Firebase 에뮬레이터, JVM의 등록/온보딩 상태 테스트, Android 에뮬레이터의 큰 글씨 안내·재확인·계속하기로 수행한다. Android 테스트의 제공자 응답은 대역이며 실제 Apple 로그인이나 토큰 폐기를 검증했다고 주장하지 않는다. 실기기 및 운영 배포는 하지 않는다. 서버 삭제 응답을 잃고 인증까지 사라진 경우의 결과 복구 프로토콜은 남아 있어 #106을 닫지 않는다.
