# 연결 해제의 영구 진행 기록

이슈 #131의 로컬 정리 재시작·실패 복구와 #157의 새 연결 보호를 다룬다. 서버 요청 후 화면이 사라져도 처음 고른 WIPE/KEEP을 유지한다. 서버 응답이 불확실한 상태에서 선택을 바꿔 재시도하지 않는다.

## 진행 단계와 저장 경계

Room v4의 `relationship_cleanup` 단일 행에 작업 토큰, 계정/기기/로그인 세대, 원래 관계 행, 선택과 단계를 저장한다. 프로필·동기화 삭제 대상에서 이 표를 제외한다.

1. REQUESTED: 서버 요청 전에 선택과 대상 관계를 저장한다.
2. SERVER_DONE: 서버 성공/상대 해제를 확인했다. 계정 탈퇴의 Apple 안내 결과도 함께 저장한다.
3. DATABASE_DONE: 기록 삭제 또는 보관, 현재 소유자의 초안 정리, 관계 상태 변경을 진행 단계와 같은 SQLite 트랜잭션에서 커밋한다. 다른/미상 소유자 초안의 첨부 보존 정책은 유지한다.
4. SIDE_EFFECTS_DONE: 키와 파일 정리를 끝냈다. 실패하면 이 단계만 다시 수행한다. 설정 저장 실패 때문에 파일 삭제를 반복하지 않는다.
5. 설정에 완료 토큰을 저장하고 Room 작업을 지운 뒤 설정의 잠금/완료 토큰을 지운다. Room 삭제 후 마지막 설정 저장이 실패해도 다음 실행이 남은 토큰만 해제한다.

잠금 순서는 항상 DataStore → Room이다. 실제 키·파일 삭제는 현재 작업과 예상 관계를 확인한 SQLite 쓰기 경계 안에서 수행한다. 새 관계/기기 커밋, 수신·공유 기록·첨부·키 쓰기는 작업 행이 남아 있으면 거부한다. 계정 전환과 새 초대 저장은 설정의 작업 토큰으로 막는다. 이미 서버로 보낸 수락 요청이 있으면 연결 해제를 시작하지 않고 먼저 수락 결과를 확인한다. 탈퇴는 서버의 계정 삭제 절차가 해당 수락을 정리한다.

앱은 진행/실패 안내와 재시도를 제공하고, 백그라운드 동기화는 저장된 정리를 먼저 이어간다. 설정 화면의 선택도 원래 값으로 잠근다. 오류를 숨겨 성공으로 표시하지 않는다.

## 검증

실제 파일 Room/DataStore를 닫고 다시 여는 테스트로 WIPE 파일 실패, KEEP 키 실패, 최종 설정 저장 실패, Room 삭제 후 설정 실패, 독립 DB 연결의 새 관계 쓰기와 경합을 확인한다. 미완료 작업이 새 첨부·본문·키·계정·수락 저장을 막고 백그라운드 동기화가 재개하는지, 먼저 보낸 수락 요청이 해제보다 우선하는지도 확인한다. Room v1~v3 이전과 기존 초안 보존·DB 롤백 키 보존 테스트를 유지한다. Android 실기기 대신 에뮬레이터에서 Keystore·파일·DB/설정 재개방을 검증한다.

## 남은 전체 수명주기 범위

이 PR만으로 #131/#157/#106을 닫지 않는다. 서버가 계정을 삭제했지만 응답을 잃고 인증까지 만료된 경우에는 클라이언트 작업 토큰으로 서버 결과를 안전하게 조회/재개하는 별도 프로토콜이 필요하다. REQUESTED 상태에서 서버를 재호출하는 것만으로 그 경우를 해결했다고 보지 않는다. 정리가 끝난 뒤 예전 화면이 들고 있던 쓰기 권한의 전체 세대 검사와 모든 플랫폼의 확장 작업 경계도 별도 감사 대상이다.
