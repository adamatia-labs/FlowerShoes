# Apple 토큰 요청의 재시도와 보존 경계

이슈 #106의 일시적인 토큰 폐기 실패를 다룬다. Apple 폐기는 동일 토큰으로 최대 3회 요청한다. 네트워크 오류, 시간 초과, HTTP 408/429/5xx만 재시도하며 그 외 거절은 즉시 수동 안내 결과로 넘긴다. 기본 간격은 250ms, 500ms다. Retry-After가 있으면 최대 2초 범위에서 따르고 그보다 긴 대기 요구는 반복 요청 없이 수동 안내로 넘긴다.

각 요청은 응답 본문까지 5초로 제한한다. 일회용 authorization code 교환은 응답을 잃었을 때 이미 소비됐을 수 있으므로 자동 재시도하지 않는다. 기존 pendingExchanges 표시를 남겨 이후 탈퇴에서 자동 폐기를 확정했다고 안내하지 않는다.

폐기 재시도가 끝날 때까지 서버의 기존 토큰을 보존한다. 성공 여부를 탈퇴 기록에 저장한 뒤 토큰과 사용자 데이터를 삭제하는 기존 순서를 유지한다. 실패가 계속돼도 계정 삭제는 수행하고 수동 해제를 안내한다. 별도 장기 재시도 큐나 토큰 복사본을 만들지 않으며 요청·토큰·응답 내용을 로그에 기록하지 않는다. 서버의 [Apple 계정 삭제 지침](https://developer.apple.com/documentation/technotes/tn3194-handling-account-deletions-and-revoking-tokens-for-sign-in-with-apple)을 기준으로 한다.

단위 테스트는 재시도 성공, 영구 실패, 최대 횟수, Retry-After, 요청·본문 시간 초과와 단일 사용 코드 보호를 검증한다. Firestore demo 에뮬레이터는 재시도 중 토큰 보존, 최종 삭제, Auth 정리 재시도 때의 Apple 결과 재사용을 확인한다. 실제 Apple 호출이나 배포는 하지 않는다.

이 변경만으로 #106을 닫지 않는다. 앱의 Apple 연결/로그인에서 토큰 저장 실패를 알리고 복구하는 경로와, 서버 삭제 응답을 잃은 뒤 인증 없이 결과를 복구하는 프로토콜은 별도 작업으로 남는다.
