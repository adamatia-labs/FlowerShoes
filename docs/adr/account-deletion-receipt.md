# 인증을 잃은 탈퇴 요청의 결과 복구

계정 삭제 요청 전에 저장한 `relationship_cleanup`의 UUID 작업 토큰과 원래 UID를 서버에 함께 보낸다. 서버는 인증된 UID와 기대 UID가 같은지 확인한 뒤 토큰의 SHA-256 해시를 기존 삭제 기록에 저장한다. 토큰 자체를 서버 기록이나 분석 이벤트에 남기지 않는다.

결과 조회는 UID와 작업 비밀이 모두 맞아야 완료 여부와 Apple 안내 결과를 반환한다. 잘못된 비밀이나 없는 기록은 같은 미완료 응답을 반환한다. 조회로 계정 삭제, 제공자 연결 해제, 새 계정 생성을 시작하지 않는다. 서버 기록을 직접 읽는 Firestore 권한도 열지 않는다.

제공자와 데이터 정리가 끝나고 Auth 삭제 단계에 진입한 뒤 최종 결과 저장 전에 종료됐다면, 실제 Auth 사용자 부재를 확인하고 같은 서버 기록의 버전이 유지됐을 때 완료 결과만 확정한다. 원래 실행이 뒤늦게 완료돼도 같은 결과를 보존한다. 제공자 응답이 불확실하거나 앞 단계에서 중단된 요청은 완료로 추측하지 않는다.

클라이언트는 별도의 로그인하지 않는 Firebase SDK 인스턴스로 결과를 조회한다. 기본 계정의 만료된 인증 토큰이 조회를 막거나 새 로그인 계정이 삭제 대상이 되는 것을 방지한다. 완료 결과가 없을 때만 현재 SDK UID를 확인해 원래 삭제를 요청하며, 실제 서버에서도 기대 UID를 다시 검사한다. 취소는 삼키지 않는다.

완료 결과는 기존 Room 진행 기록에 저장한 다음 파일·키·설정을 원래 선택대로 정리한다. 로컬 정리가 끝날 때 기존 작업 토큰도 지워진다. 서버의 해시는 기존 계정 삭제 tombstone과 함께 남아 옛 토큰의 계정 재생성을 막는 정책을 유지한다. 기존 서버에서 비밀을 등록하지 않은 과거 요청을 무인증으로 복구할 수 있다고 주장하지 않는다. 새 서버 함수를 먼저 배포해야 한다.

검증 범위는 응답/인증 유실 뒤 Room/DataStore 재개방, 계정 전환, 취소, 잘못된 작업 비밀, Auth 삭제 전후 중단과 최종 완료 저장 경합이다. 로컬 Firebase의 Auth/Firestore/Storage 테스트와 Android SDK 통합 검증을 사용하며 운영 프로젝트에는 배포하지 않는다. 이 수정만으로 #131의 모든 오래된 화면 쓰기 권한을 해결했다고 보지 않는다.
