# 쓰던 편지의 계정과 편집 경계

#153의 초안은 소유자 없는 전체 목록과 upsert를 사용했다. 같은 기기의 다른 계정이 읽거나 덮어쓰고 삭제할 수 있었고, 연결 해제는 모든 초안을 지웠다.

## 소유자와 편집 권한

Room v3은 `letter_draft`에 nullable `ownerUid`와 `editorToken`, 첨부 보존 표시 `hasAttachments`를 추가한다. v1→v2→v3 이전에서 기존 내용과 시각은 보존하며 소유자는 null로 남긴다. 파괴적 이전은 없다.

편집을 열 때 현재 DataStore의 계정·기기·로그인 세대를 확인하고 SQLite 쓰기 경계에서 임의 편집 토큰을 발급한다. 다른 계정과 소유자 미상 행은 열지 않는다. 새 편집은 빈 예약 행을 만들며 목록에는 보이지 않는다. 저장은 소유자·id·편집 토큰이 모두 맞는 기존 행만 갱신한다. 다른 편집이 열리거나 행을 지우면 이전 저장·보내기 완료 콜백은 내용을 되살리거나 새 편집을 삭제할 수 없다.

DataStore는 계정 전환마다 임의 로그인 세대를 만들고 계정별 마지막 세대를 보관한다. A→B→A→B처럼 관찰자가 중간 전환을 놓쳐도 옛 A 편집은 다시 유효해지지 않는다. 테마 변경이나 같은 계정의 일반 설정 변경은 세대를 바꾸지 않는다. 신원 캐시가 늦게 갱신되더라도 모든 권한 발급·삭제·복구는 실제 설정 쓰기 경계에서 확인한다.

## 입력 보존과 화면

전환 전에 이미 발급한 편집 권한과 마지막 입력을 함께 잡아 두고 원래 계정에만 마저 저장한다. 다른 계정이 활성 상태이고 해당 소유자가 아직 재로그인하지 않았을 때만 허용한다. 삭제된 행, 새 편집 토큰, 탈퇴 정리, 기기 변경에는 적용하지 않는다. 이 경로는 새 편집을 만들거나 다른 계정의 초안을 읽지 못한다.

계정 세대가 바뀌면 목록과 열린 편집의 본문·사진·그림·보냄 화면을 비우고 새 권한을 기다린다. 지연된 사진 선택, 그림 저장과 썸네일 읽기는 시작한 편집 토큰에만 반영한다. 같은 초안을 다시 열어도 이전 콜백은 새 편집에 적용하지 않는다. 편지에 붙이는 그림판은 편집 토큰마다 독립 ViewModelStore를 사용하며 화면이 사라지거나 토큰이 바뀌면 이전 그림·저장 작업·완료 이벤트를 폐기한다. 전송 중 화면을 닫거나 계정을 바꿔도 전송 전 본문을 저장하며 성공한 전송만 해당 편집 토큰으로 삭제한다. 자동 저장의 중복 방지 기록은 실제 저장 성공 뒤에 갱신해 저장 실패 후 같은 내용을 다시 저장할 수 있다.

보내기는 전송 시작 시의 편집 권한을 고정한다. 실제 DataStore 계정 확인과 편지·전송 기록 저장을 같은 Room 트랜잭션 안에서 수행하고, 발신 UID·기기·키 세대도 고정해 늦게 갱신되는 신원 캐시를 다른 계정의 전송에 사용하지 않는다. 완료 화면은 마지막 비동기 읽기 후 토큰을 다시 확인한다. 늦은 전송 완료는 같은 초안에 새로 발급한 편집을 삭제하지 못한다.

## 기존 초안 복구

소유자 미상 초안은 로그인만으로 귀속하지 않는다. 로그인한 화면에는 내용 대신 개수와 확인 동작만 보인다. 사용자가 작성했던 계정으로 로그인했고 본인이 쓴 편지임을 명시적으로 확인하면 현재 계정으로 복구한다. 확인 중 계정이 바뀌면 이전 확인을 적용하지 않는다. 이전 DB에 소유자 정보가 없으므로 기술적으로 원래 계정을 증명한다는 뜻은 아니다. 복구는 이 기기의 목록에만 추가하며 자동 전송·동기화는 하지 않는다.

## 연결 해제와 탈퇴

연결 해제는 같은 DB 트랜잭션에서 현재 계정의 초안만 지우고 편집 세대를 무효화한다. 다른 계정·소유자 미상 초안은 남긴다. 본문이 있는 이러한 초안이 남으면 첨부 DB와 파일도 보수적으로 보존한다. 첨부를 만들기 전에 현재 편집에 보존 표시를 영속화하므로 자동 저장 전 사진·그림도 보호한다. 첨부도 없는 빈 예약 행은 파일 삭제를 막지 않는다. 첨부 생성이 실패하거나 취소되면 보수적인 표시가 남을 수 있고, 해당 초안 삭제 또는 그 소유자의 연결 해제에서 정리한다. 구버전 JSON에서 모든 참조를 확정할 수 없어 관련 없는 첨부까지 남을 수 있지만, 보존하기로 한 초안의 사진을 삭제하지 않는다. 공유 편지·그림 등 나머지 기록은 기존 KEEP/WIPE 선택에 따른다.

탈퇴 정리 중에는 새 초안 권한 발급을 막는다. 전체 서버/로컬 해제 저널과 다른 화면의 계정 경계는 #131에서 별도로 다룬다.

## 검증

실제 Room/DataStore 테스트는 다른 계정 조회·수정·삭제 거부, 기존 소유자 미상 보존, 계정 세대 재사용 거부, 편집 토큰 교체와 삭제 뒤 늦은 저장 거부, 진행 중 목록 무효화, 첨부 보존, 탈퇴 중 편집 거부를 검사한다. UI 테스트는 계정 전환 시 원래 입력 보존과 화면 초기화, 저장 실패 뒤 재시도, 이전 사진 콜백 거부를 확인한다. Android 에뮬레이터 테스트는 실제 렌더링된 편집 화면과 파일 DB 재개방을 함께 확인한다.
